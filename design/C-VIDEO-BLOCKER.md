# Video provider status (Agent C, 2026-09-23)

Cloudflare Stream is wired but not usable for uploads yet. The repo-root `.env.local` holds `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_KEY` (names only), and the stored credential was proven to be a Bearer API token rather than a Global API Key: `GET /accounts/{id}/stream?per_page=1` answered HTTP 200 and `GET /user/tokens/verify` answered HTTP 200 with status `active`. The `CloudflareStreamVideoProvider` adapter (CQ-MEDIA-010) composes from those two and was exercised live: asset status and deletion behave as documented. **Blocker 1 — no Stream allocation on the account:** a live one-time direct-upload reservation (60 s, 5-minute expiry) was refused with HTTP 413, vendor code 10011, "Storage capacity exceeded … allocated 0 minutes", and `GET /accounts/{id}/stream/storage-usage` reports `totalStorageMinutesLimit: 0`. Stream is not subscribed; fix in the Cloudflare dashboard → Stream → enable the subscription (billed per 1,000 minutes stored and delivered). No code or variable change is needed; until then every upload attempt surfaces as `503 PROVIDER_UNAVAILABLE`, never as a success. **Blocker 2 — playback:** `CLOUDFLARE_STREAM_CUSTOMER_SUBDOMAIN` (the `customer-<code>.cloudflarestream.com` host from Stream → Settings) is absent, so `createPlaybackAuthorization` rejects with `MediaProviderNotConfiguredError` (`MEDIA_PROVIDER_NOT_CONFIGURED`, naming that variable). Optional: a signing key pair `CLOUDFLARE_STREAM_SIGNING_KEY_ID` + `CLOUDFLARE_STREAM_SIGNING_KEY_PEM` from `POST /accounts/{id}/stream/keys`; without it the adapter asks the vendor's token endpoint per playback. Exact setup: (1) enable Stream on the account, (2) set `CLOUDFLARE_STREAM_CUSTOMER_SUBDOMAIN`, (3) optionally set `CLOUDFLARE_STREAM_API_TOKEN` to the existing token value (the `CLOUDFLARE_API_KEY` spelling is accepted as an alias) and the two signing-key variables. Full detail in `docs/modules/media-cloudflare-setup.md`.
