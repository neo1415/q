# Video provider status (Agent C, updated 2026-09-23)

Cloudflare Stream is wired and uploads work. The repo-root `.env.local` holds `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_KEY` (names only); the credential was proven to be a Bearer API token (`GET /accounts/{id}/stream?per_page=1` HTTP 200, `GET /user/tokens/verify` HTTP 200 `active`). The `CloudflareStreamVideoProvider` adapter (CQ-MEDIA-010) and the direct upload flow (CQ-MEDIA-011) are merged, and after the account's Stream subscription was enabled the full leg was proven live: reservation → a 33,832-byte WebM POSTed to `upload.cloudflarestream.com` → `PROCESSING` → `READY` → delete. The earlier 413/10011 "allocated 0 minutes" refusal is resolved. **One blocker remains — playback:** `CLOUDFLARE_STREAM_CUSTOMER_SUBDOMAIN` (the `customer-<code>.cloudflarestream.com` host from Stream → Settings) is absent, so `POST …/pitch/:mediaAssetId/playback` answers `503 PROVIDER_UNAVAILABLE` with `MEDIA_PROVIDER_NOT_CONFIGURED` naming that variable; nothing fakes a token or a playable pitch. Optional: a signing key pair `CLOUDFLARE_STREAM_SIGNING_KEY_ID` + `CLOUDFLARE_STREAM_SIGNING_KEY_PEM` from `POST /accounts/{id}/stream/keys`; without it the adapter asks the vendor's token endpoint per playback. Exact setup: (1) set `CLOUDFLARE_STREAM_CUSTOMER_SUBDOMAIN`, (2) optionally set `CLOUDFLARE_STREAM_API_TOKEN` to the existing token value (the `CLOUDFLARE_API_KEY` spelling is accepted as an alias) and the two signing-key variables. Full detail in `docs/modules/media-cloudflare-setup.md`.
