## 4. Dependency direction

The graph is read from each `package.json` `dependencies`, with workspace edges only.

- **No package depends on an app.** The only `apps`-looking strings inside packages are owner labels such as `handlerOwner: "@capital-q/workers"` (`packages/discovery/src/jobs/index.ts:50`), not imports.
- **No declared cycles** (a DFS over all 52 packages finds none).
- **Subpath imports** (`@capital-q/config/database`, `@capital-q/security/postgres`, `@capital-q/model-gateway/q`, `@capital-q/network/events`, `@capital-q/evidence/contracts`, …) all go through declared `exports` maps (e.g. `packages/config/package.json` exports 16 subpaths), so they are public entrypoints, not deep imports.
- **Mis-declared dependency:** `packages/q-orchestrator` imports `@capital-q/q-core` at runtime (`packages/q-orchestrator/src/workforce/review-loop.ts:4`, `src/work/lane.ts:1`) but lists it only under `devDependencies` (`packages/q-orchestrator/package.json:49`). It resolves inside the workspace, but a production-only install or `pnpm deploy` of this package would break.
- **Apps depend on almost everything:** `apps/q-api` declares 48 workspace packages, `apps/api` 36, `apps/workers` 34, `apps/web` 9 (`api-client, config, contracts, founder-onboarding, gateq, investor-onboarding, onboarding, q-core, ui`).

Observations:

- `model-gateway` sits at L10 because it depends on `evidence`, `q-runtime`, `q-core` and `database` (`packages/model-gateway/package.json`). The "one provider-neutral inference boundary" is coupled to the Q runtime and evidence domains, so any change to those packages rebuilds the gateway.
- `security` (L2) depends on `database` and `@supabase/supabase-js`. Authorization primitives and the Supabase adapter share one package, separated only by subpath exports (`./postgres`, `./supabase`).
- `app-actions` (ADR 0040, status "Proposed" in its own description) depends on 19 domain packages and is consumed by `q-tools`, `api` and `q-api`. It is the de-facto mutation registry for the whole product (02 §3).
