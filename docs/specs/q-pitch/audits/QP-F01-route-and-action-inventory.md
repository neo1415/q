# QP-F01 — Route and navigation-action inventory

Read-only audit for blueprint §5 ("No per-click LLM browsing") and §11 P0. Branch `claude/q-pitch-foundations`, cut from `origin/build/int-rc` at `be2ab28a`. File:line references are against that tree.

**Verdict:** the app already has three acknowledged, typed client-side paths. The Q Pitch tour director must dispatch **only** through them. It needs no new navigation primitive, selector, URL or DOM access.

## 3. Gap found that is needed by the certified scenes (flag)

Three of the four certified claims are produced by a **governed Q question**, not by navigation:

- `INV-DISCOVER-TOP3`
- `INV-PROFILE-FINDINGS`
- `INV-RISKS-FOLLOWUP`

The blueprint §5 primitive list has no "ask Q an approved question" primitive. `TourAction` v1 therefore adds **`askApprovedQuestion`**, backed by path C. It carries only an approved question id, never free text, and Q answers through the normal governed path and Context Firewall (blueprint §9: "Q can still answer fresh investor questions through the governed general Q path").

This is recorded as **PROPOSED r2: add `askApprovedQuestion` to the §5 primitive list (Lane B, 2026-10-13)** for product-owner approval. It is not yet in the blueprint changelog.

## 4. Routes the P1 pilot uses

All three are in `APP_ROUTE_PATTERNS`:

- `/discover` (`NAVIGATE DISCOVER`);
- `/company/[companyId]` (`OPEN_RECORD_PAGE COMPANY`);
- the Q answer canvas on the current page, for comparison cards.

The live journey that produced the certified receipts is `scripts/handoff/live/investor-demo-rehearsal.mjs`.
