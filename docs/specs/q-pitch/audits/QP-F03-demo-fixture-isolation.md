# QP-F03 — Demo fixture isolation

Read-only audit for blueprint §4 ("Preferred environment") and Doc 23 §117 / §231.

**Verdict:**

- Reference and demo seeds are separated in code.
- Fictional accounts are classified.
- The demo data used by the certified scenes, however, lives in the **production** deployment.
- Whether that project is the attested "synthetic" project cannot be confirmed from the repository.

A dedicated showcase environment does not exist yet.

## What must change for a showcase environment (owner and integration-owner decisions)

1. **Environment.**
   - Decide between a separate showcase or staging deployment (preferred by blueprint §4) and production with fictional tenants.
   - If production: record an ADR stating that fictional tenants coexist with production data, and confirm the attested project ref.
2. **Release pinning.** The showcase runs the same released commit, with its own `CAPITAL_Q_SYNTHETIC_SUPABASE_PROJECT_REF`. The demo seed is run only there.
3. **Fixture snapshot.** `SceneEvidence.fixtureVersion` needs a stable identifier for the seeded world. The seed writes `manifest.json` to `.tmp/fictional-world`; versioning it (not committing private data) gives that identifier.
4. **Actor allow-list.** Tour actors must be `@fictional.capitalq.local` accounts with `fictional_demo` metadata. The Lane B contract rejects any other actor email (`packages/q-pitch`, `TourActorSchema`).
5. **Viewer access.** Shared viewer access must expire, be rate-limited, logged and confined to demo fixtures (blueprint Appendix B). None of this exists yet; it is P4 work.
