# QP-F02 — Dual-membership capability (one sign-in, founder and investor organisation)

Read-only audit for blueprint §4. No auth path is built here.

**Verdict: CAPABLE at the schema, API and web-switcher level. NOT YET SAFE for the §8 privacy demonstration without the integration owner's work.** Membership-based RLS does not separate the two roles of one person.

## What is missing (owner: integration owner, QP-F10; not Lane B)

1. **Privacy-demonstration integrity.**
   - With one person holding both memberships, "investor Q cannot see the founder's private document" is true only by the server's active-context scoping. At the identity and RLS layers the person *is* an authorised founder member.
   - Blueprint §4 and §8 present the denial as an authority boundary. With one shared sign-in, that boundary is the active context, not identity.
   - **Recommendation:** use two separate fictional sign-ins (one founder, one investor) for the privacy scene, or have the owner approve an explicit statement of what the denial proves. Escalate to the product owner; possible PADL/blueprint conflict.
2. **Switch invalidation.** The activate path does not yet re-scope Q:
   - conversation run scope;
   - Q memory;
   - prefetch caches;
   - pending approvals.

   Blueprint §4 and §12 require all of these to switch atomically. `activate-organisation.ts` lists them as future hooks.
3. **No Q client action** for a switch. `switchDemoContext` would need a typed, acknowledged intent: an `ActivateOrganisationResponse` plus the post-refresh route and viewer kind observed. That is a shared contract and needs the integration owner.
4. **No demo dual-membership fixture.** No seed creates a person with both memberships. `apps/q-api/src/dev/fictional-world/accounts.ts` creates one founder account per company and one investor account per firm. A join path (`team.invite` / `team.invitation.accept` app actions) exists and could link them without a new auth path.
5. **The default-context precedence** (founder wins) should be replaced by "active membership required" for dual members, so a missing `user_active_contexts` row can never silently pick a role.

**Lane B therefore treats the actor as an input to the tour director.** A `ROLE_SWITCHED` event clears every capsule scoped to the old actor, and actor-mismatched capsules are refused. No switch is executed from the tour in v1.
