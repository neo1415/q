## 4. What was tried, and why fixes passed tests but failed live

- **Main lesson.** The onboarding tests use **fake readers and choosers** that return exactly the shape a fix expects. The live models return other shapes, so fixes passed hundreds of tests and then failed live: traction words never reached `beyond`, and a yes to their words wrote the mapped category. **Before deploying any onboarding or reader fix, replay the actual live transcripts through the real models**: a few cents of OpenAI, and owner approval is needed for provider spend. Record them as fixtures the way research acceptance does.
- **Regressions we caused, then fixed:**
  - typed replies made to wait for the full reading took 12–22 s; reverted, now ~4 s;
  - reader v13 split list items, so each overwrote the last ("Nordics and Germany" → Germany); `a015597c4` merges them per step;
  - a model-input change broke the recorded research replays in CI;
  - an unused import;
  - a `structured-mandate` version pin in a test.
- **Designs considered and rejected:**
  - Going back to one model call that both replies and saves. The owner pointed out that is the pre-27 Oct design we patched for weeks. The conversation-first, transcript-reader design stays (DECISIONS 39); fix the seams between reply and reader instead.
  - Rolling back production by force-pushing the deploy branch. Not done without owner approval; we fixed forward.
- **Patching loop:** each live check found new edge cases, and "perfect" had no stopping rule. Rule from 31 Oct: fix only **data loss/corruption and evidence dishonesty** before stopping; everything else goes on the list.
