# Artifacts live: 20 October 2026

**Owner ask.** As Q talks, the artifact for what it is saying comes up at that moment.

- A company, investor or person shows with its real logo or photo, else initials.
- A visual topic shows a picture from an authorised source, with attribution.
- Comparisons are tables; summaries are a summary artifact.
- Research is arranged as it arrives.
- While Q works, it says where it is, in approved stages only.
- A skeleton appears within about 300 ms of Q naming the thing, then fills.

### Latency on the naming → artifact path (before → after)

| Step                                                          | Before                                                                                                                                     | After                                                                                                                                                                                                                                                   |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Q names a company in a streamed sentence → anything on screen | Nothing until `q.message.completed`: the whole answer, its object tail and the persist. Typically several seconds after the first sentence | The preview rides **in the same bus frame** as the naming sentence: `index.ts` `sendSaid`, then `q-runtime` `deltaEvents` emits `q.artifact.preview` immediately before the sentence's `q.message.delta`. Same SSE flush, so 0 ms added server-side     |
| Preview frame → skeleton drawn                                | n/a                                                                                                                                        | `live-preview.tsx` is statically imported (no lazy chunk). It renders in the same React commit as the sentence text. Expected render cost under 16 ms; **not measured in a browser** (see §4)                                                           |
| Skeleton → real logo                                          | n/a                                                                                                                                        | `<img>` is lazy. The photo route is one API read. On a 404 the logo route makes one API read plus, once per site per 24 h, the vetted site fetch (≤ 3 s timeout per hop, at most 4 candidates). A miss is cached 3 h server-side and 1 h in the browser |
| Answer lands → real cards                                     | Lazy `stage-canvas` chunk (prefetched at follow)                                                                                           | Unchanged. The preview's frames are replaced in place, and the replaced set does not fly to the Board over the new cards                                                                                                                                |

## 5. Deploy notes

- `q.artifact.preview` is additive and ephemeral. An older web silently skips a frame its contract does not know (`api-client` `streamQRunEvents` drops unparseable frames). Deploy order does not matter.
- `/v1/companies/:id/profile/logo` is new on api; the web logo route 404s until api has it. The avatar then shows initials.
- No migration.
