# Meetings speed — 2026-10-20 (Claude, branch `claude/meetings-speed-e29305`)

Owner brief: Q in meetings is too slow. Targets: Q's spoken reply starts within
about 1.5 s of being addressed; preparation happens before the meeting; notes
and follow-up cards are ready within seconds of the end; no model call where
code can compose the answer.

Scope: meeting composition and presence (`apps/q-api/src/composition/meeting-*`,
`recall-bots.ts`, `tavus/*`, `http/meeting-face.ts`), the meeting host machine
and meeting assistant service in `packages/communication`. Not the general Q
turn pipeline, voices, arrival, onboarding or artifacts.

Not on the meeting path (checked, nothing to fix here): `composition/presence.ts`
and `packages/q-presence` are the public web-presence builder
(CQ-Q-PRESENCE-001); `composition/recall-graph.ts` is the connected-recall
memory graph (q-knowledge), not Recall.ai. `schedule-actions.ts`, `own-calls.ts`
and `slots.ts` book calls; they make no call inside a meeting (the only touch
point is `joinCallNow.book`, which already enlists the bot at once).

Timings: "est." = estimated from code, budgets and earlier ledgers (the gateway
comment records the dialogue model at 3.4 s p95 on a healthy day); "test" =
measured with fake providers in vitest (local timing, no provider reached).

### Shared-code changes (minimal, listed)

- `packages/communication`: `MeetingHost.replyPart` / `nextWakeAt` (host.ts),
  `readIntroduction` (new introduction.ts), thumbnail-based change in
  screen.ts (`thumbDifference`, optional `thumb` on frames, optional
  `minChange`/`recheckMs` limits), optional `meetingId` on the notes composer
  input, record() parallelism (service.ts). Exports added to index.ts.
- `apps/q-api/src/main.ts`: one rolling-notes composer shared by the host
  runtime and the meeting assistant.
- No contract, migration, authorization or prompt change. The model gateway
  is used through its existing `onTextDelta` / `firstAttemptTimeoutMs`.

### Open

- Live latency on a real call is not measured here (no paid rooms without the
  owner's OK). The structured log `meeting host spoke` now carries
  `streamed`, `heardToComposedMs` and `heardToAudioMs` per answer for the
  first live call.
- Change thresholds (6 / 16) are first estimates; tune from live logs.
- Rolling notes live in the hosting q-api process: if the provider webhook
  lands on another instance, notes are composed whole (old behaviour).
