# Turn latency — 20 October 2026 (Claude, `claude/turn-latency-6a96d1`)

**Purpose:** list every model call, wait and read in an ordinary Q turn (typed and GPT-Live), what each costs, and what this branch changed. The owner wants Q to feel like Kuuza: one short model call per turn, and code-only moves.

**Scope:** the conversation/turn pipeline, the gateway `q/` readers and the live voice line. Arrival, onboarding, artifacts, rehearsal voices, meetings and the ElevenLabs provider belong to other sessions and are not touched.

**Sources:** timings marked _measured_ come from `PERFORMANCE-BASELINE.md`, `STATE.md` and `Q-CONVERSATION-FIXES-2026-10-17.md` (production ledger samples, single observations, not p50/p95). Rows marked _est._ are read from code and budgets. No new live measurement was made on this branch. It is not deployed.

## 5. Before and after, model calls per turn (deterministic tests)

| Turn                                           | Before                                             | After                        |
| ---------------------------------------------- | -------------------------------------------------- | ---------------------------- |

| "Open the data room" / "now the pitch deck"    | 2 early (skim, reading) + 0–1 later                | **0** on a page with the tab |

| Typed first question                           | 3 (skim, reading, answer)                          | 3 (unchanged)                |
| Spoken follow-up after cards                   | skim, reading, (speculated) answer                 | unchanged                    |
| Page by its name, pleasantry, own mandate, fit | 0                                                  | 0                            |

Expected wall clock (from the measured stage times above, not re-measured live): the second-one recall 3.3 s → one DB read plus one insert (~0.3 s end to end); a tab on the current page 1.6–2 s → the same frame in the browser (Q's line follows). A live check is needed after deployment.
