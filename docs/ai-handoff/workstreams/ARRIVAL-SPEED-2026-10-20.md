## The path as traced in code

1. **Server render.** `/home`: `app/(app)/home/page.tsx` → `HomeScreen` (`features/home/home-screen.tsx`) → `ReturningWelcome` → `ArrivalBriefing variant="page"`, with `ArrivalStage` as the Q stage layer. The greeting text is server-rendered as `ArrivalBriefing`'s fallback (`greeting.headline` + `OPEN_QUESTION`). `welcomeLine` goes to `QConversationPanel` for the voice.
2. **After hydration.** `useArrival` → `startArrival` (`arrival-store.ts`) → `decideArrival` (`arrival-gate.ts`; sync storage, about 0 ms) → `loadArrival` (`arrival-browser.ts`). Before this change that was a **server action**, `arrivalBriefingAction` (`arrival-actions.ts`).
3. **The read on the server** (`readArrival`, now `arrival-read.ts`): about 14 reads across the api and q-api, including q-api `GET /v1/q/arrival-snapshot` (`http/q-arrival-snapshot.ts` → `createArrivalSnapshots.forActor`). That call is one probe query, then a cache hit or a cold build (attention + relationship briefs; live 2026-10-15: 1.4 s, 126 round trips), plus the Q Daily edition.
4. **Data arrives.** `arrivalWords` (pure code; no model) composes the greeting, the opener and the counts. `setArrivalSpoken` runs, the stage gets its cards, and `handedLate` sends the lowdown to an open voice line (`noteToLine`).
5. **Voice.** `QConversationPanel` auto-talk (`setTimeout 0` → `microphoneGranted` → `talk`) opens the line at once with `welcomeNow(...)`, which uses the arrival's words when ready and the server's `welcomeLine` otherwise. **No model call comes before the first words.** Opening the line itself (GPT-Live/ElevenLabs connect) belongs to the voice provider files, which this lane does not own.
6. **Follow-ups on welcome items.** Example: "what did they say?". The flow is `packages/model-gateway/src/q/index.ts` `decideArrival` → `arrivalFollowUpAnswer` / `arrivalAspectAnswer` (`arrival-answer.ts`, pure), from the snapshot. That is 0 DB round trips inside the 30 s trust window and one probe query after it. There is no tool read and no model call. `withoutWideReads` skips the wide reads for "what needs me".

| ---------------------------------- | ------------------------------------------------------ | ----- |
| founder, snapshot warm             | 530                                                    | 220   |

- **Cold, as the browser sees it.** With #2 the cold build starts at server render, so the browser's read waits only for what is left: `max(0, 1400 − (SSR + download + hydrate))` plus the rest.
- **The action queue (#3).** Its saving does not show in these numbers, because the model times only the read.
- **The down case** is 30 ms slower by design: the attention fallback now waits to learn that the snapshot failed.
