## 2. How code reaches production (follow exactly)

1. **Branch from the integration branch.** Work in your own worktree, one owner per branch, small commits.
2. **Pre-gate**, all heavy work through the machine lock:
   - run `bash scripts/heavy.sh <cmd>`;
   - `pnpm exec turbo run build --filter=./packages/*` first, because stale `dist` gives false type errors;
   - targeted `vitest`, the root `tsc` (`node --max-old-space-size=7168 node_modules/typescript/bin/tsc --noEmit -p tsconfig.json`), each touched app's `tsc`, eslint and prettier on changed files;
   - `scripts/pre-gate.sh` runs changed packages, their dependents, integration tests and the bundle budget.
3. **Commit, then push** to `fix/resume-asking-cv9ru3` **and** the mirror `claude/confident-keller-v0ug6h`. In a new account, use whatever branch your session is told to use, but keep both up to date.
4. **Run ONE local gate per batch, on the exact SHA:**

   ```bash
   NODE_OPTIONS=--max-old-space-size=8192 CI_LOCAL_REF=<sha> bash scripts/ci-local.sh
   ```

   - The receipt is its last line, `ci-local PASS sha=…`, taking about 22–25 min.
   - `NODE_OPTIONS` must **not** contain `--use-openssl-ca`, which breaks the Next build after a container restart.
   - Keep more than 4 GB of free disk. A run died once at 1.7 GB; free space by deleting scratch.
   - Check `/tmp/ci-local/gate.owner` before starting. A second gate exits with 75.

5. **Migrations go BEFORE the deploy, never in parallel**, and only after the gate's pgTAP step passed:

   ```bash
   SUPABASE_ACCESS_TOKEN=proxy-injected node scripts/handoff/hosted-migrate-https.mjs --apply <version>
   ```

   - It refuses DROP, RLS loosening and `delete from`.
   - `--founder-approved <version>` is only for an exception the owner reviewed explicitly. It was used once, for 599700.

6. **Deploy only with the promote script:**

   ```bash
   PATH=/opt/node24/bin:$PATH NODE_USE_ENV_PROXY=1 bash scripts/deploy-promote.sh <full sha>
   ```

   It needs the PASS receipt for that SHA, fast-forwards production and prints the rollback point. Write the rollback point down.

7. **Live-verify straight away:**
   - `scripts/handoff/live/railway/deploys.mjs` shows all SUCCESS;
   - `qlogs.mjs <sha> "57014|DB_POOL|\"level\":50" HH:MM:SS HH:MM:SS` must be empty;
   - one Q turn as fictional Savanna with `browser/q-turn.mjs`: first text arrives in about 2.6 s and the answer is sane;
   - `browser/routes.mjs` if you touched the web.
8. **Write it down:** a ledger entry (SHA, gate time, what is in it, the live evidence, what was _not_ live-checked and why). Update `STATE.md` and `ACTIVE-TASKS.md`, append to `HANDOFF-LOG.md`, then push.

**Never:**

- force-push;
- re-add GitHub Actions push triggers (decision 88: CI is local and Actions minutes are the owner's);
- run `scripts/handoff/live/railway/deploysha.mjs`;
- deploy without a receipt;
- run a migration in parallel with a deploy.

Remote branch deletes are refused by the proxy (403), so leave merged branches alone. The owner can delete them.
