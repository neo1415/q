# RC3 latency: before and after (Q voice audit, 15 Nov 2026)

Deterministic replay over the audit's recorded turns (`investor-turns.jsonl`, `founder-turns.jsonl`). No model, no tool, no network: `node scripts/handoff/latency-replay.mjs` routes every recorded Q turn through the real execution-class code (`packages/q-core` `turnExecutionClassOf`) and costs it before (as recorded) and after (this change's rules applied to the recorded numbers). Interview (J) and rehearsal (K) turns are not the Q answer seam and are left out.

## What changed (RC3)

1. **Execution classes** (`contracts` `TURN_EXECUTION_CLASSES`, `q-core` `turnExecutionClassOf`, `q-specialists` `executionReadingOf`): CONVERSATIONAL_ACK, CONTEXTUAL_FOLLOW_UP, ANSWER_FROM_CONTEXT, NAVIGATION, STRUCTURED_QUERY, COMPLEX_ANALYSIS, MULTI_SOURCE, PUBLIC_RESEARCH, CONSEQUENTIAL_ACTION, read from the turn reader's structured fields only. An unread or low-confidence reading, a name Q has not said in the conversation, or attached files keep the full path. The class rides `QAnswerRequest.executionClass` and is logged per turn (`q turn execution class`).
2. **Conversation-scoped evidence reuse** (`model-gateway` `conversation-evidence.ts`): the account digest and the wide reads are kept per tenant + user + organisation + membership + actor type + conversation + access-context hash (policy version, ceiling, scopes, combination constraints), with provenance (the run and the reads). Reused only by a class that reuses evidence, within 3 minutes, when no write of theirs went through Q's tool seam or an approval (forgetPerson), and when the database watermark (`apps/q-api` `evidence-watermark.ts`: relationship events on either side, actions/approvals, documents, statements, meetings) says nothing changed since; a watermark that cannot answer is a miss.
3. **Parallel reads**: the cheque-fit and diligence follow-up reads wait only for the named-company reads, beside the day, standing, index, setup and arrival reads (they waited for all of them).
4. **One writer for one-call lanes**: a lane budgeted at one answer call is never split into a second extras writer (production default `CQ_Q_PARALLEL_EXTRAS` on: typed turns paid two writer calls). A lane that does not go to the public web by itself no longer has code force a search (EXPLICIT / ONLY_IF_EMPTY become OFFERED: the model still holds the tool).
5. **Spoken form** (COMPANY_ANALYST v36, `contracts` `QSpokenFormSchema` v1 on `QResponseMessage.spoken`): written by the same call from the same evidence; kept only when every figure and name in it is in the full answer (`q-core` `spokenFormWithin`), otherwise dropped, never repaired. The standard voice line speaks it on a completed (non-streamed) answer; the screen shows the full answer.

## How "after" is computed (assumptions, stated)

- **Reading.** The audit stored no turn-reader output (an instrumentation gap it names). Each turn's reading is rebuilt from the audit's own per-turn category and the person's words (lookup → LOOKUP about their own records, follow-up → FOLLOW_UP, research → RESEARCH_REQUEST, ranking → FIT or compare, action → asks for an action, navigation → NAVIGATE). The class then comes from the real code. A name in their words that Q's previous text did not contain counts as new information (no reuse), as in `executionReadingOf`.
- **Reuse.** Only when the previous Q run of the same session was within the 3-minute TTL and no approval or state change was recorded between them. Tool calls after = recorded calls minus the repeated digest/wide reads (investor `reran.calls`, bounded by those reads' own count; founder: reads repeated from the previous turn).
- **Model calls.** Recorded per run for investors only (founder per-turn model calls were not recorded). After = recorded minus the second extras writer on typed one-call-lane turns. The reader and the classifier calls are unchanged by this slice: a follow-up is answered by one answer call after the reader, not by one call in all.
- **First useful answer.** Recorded minus 1.0 s (the wide reads' critical-path time profiled in S3, `index.ts`) on a turn that reused evidence. Time spent by searches no longer forced is not estimated (no per-call timing in the records).
- **Spoken.** Recorded spoken time; after, for a turn the analyst writes, at most the spoken form at its asked length (about 60 words, 330 characters; hard bound 480) at the investor records' own measured speaking rate.

## Limits (not verified here)

- No live run: the numbers above are a replay over recorded turns, not a production measurement. Production acceptance needs the per-turn log line `q turn execution class` and the two `answered from this conversation's evidence` lines, plus model/tool counts per run, on a real session.
- **Streamed voice answers** still speak the streamed full text (`apps/q-api/src/voice/turn.ts`, voice line lane): the spoken form is used when the completed answer arrives unstreamed. Making the live line speak the spoken form while the answer streams is the voice line's next step.
- The watermark is deliberately wide (any change in their tenant or on their relationships misses), so the real reuse rate will be lower than the replay's on a busy account.
- Audio was not tested here; spoken durations are estimates from recorded characters and recorded speaking rate.
