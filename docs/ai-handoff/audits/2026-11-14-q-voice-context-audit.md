# Audit: Q voice vs Q Brain, and account context per turn (14 Nov 2026, read-only)

Owner concern (14 Nov): the voice "does its own thing" and Q answers without knowing what is happening on the account.

**Method.** Code read at `6fa572d40`. Production reads covered:

- `q_runtime.voice_line_turns`, `runs`, `run_events` and `conversation_messages` for 1–14 Nov;
- q-api Railway logs for deployment `06910b145` (14 Nov 21:19–21:30 UTC).

No model calls, builds or tests were run. Quotes are short paraphrases or ids. User ids are truncated, and personal names and message bodies are left out.

**Data window.** In the 16 days before 14 Nov, 99% of voice segments were `routed=live` (GPT-Live). Only 9 Nov had a handful of `ask_q` or `model_only` duplex turns. The live line is therefore the one to fix.

**A delegated turn gets the same context as a typed turn.** `turn.ts:1205-1220` creates an ordinary `ANSWER` run with `modality: "VOICE"`, the same `conversationId`, and the browser's `screen`/`viewing`. All 8 runs on 14 Nov carried a `screen` manifest. The Q context assembly for any turn (typed or delegated) is:

- **The situation header** (`model-gateway/src/q/situation-header.ts`, ≤1,500 chars): date and time, who is asking, their own organisation, the surface, and the record on screen. It holds **no account state**: no relationships and their status, pending approvals, booked meetings, running work or GateQ applications.
- **The arrival snapshot** (≤8 "needs you" items) among the wide reads (`index.ts:4063-4080`).
- **Tools on demand.** Code fast lanes (the fit sweep and others) answer **before** the turn reader and the wide reads (keyword-routing audit, 13 Nov, item 1).

**GPT-Live's own lines become Q's memory.** Every segment the voice said without a delegation is written into Q's conversation as a `Q` message (`live/broker.ts:1633-1655`, "B1 mirror"). This includes word-by-word fragments and unbacked promises. So the next typed or spoken Q turn reads words Q never decided.

## 3. Ranked defects

1. **P0: the voice is a second brain on the live line.** It decides when Q is consulted, answers the rest itself, invents progress, actions and questions (D3, D6, D7, D11), and paraphrases Q into claims Q did not make (D2, D4, D5, D13). This reverses the 8 Oct VOICE-BRAIN rule that the duplex line still enforces in code.
2. **P0: Q has no standing account-state context.** The situation header holds identity and page only. Relationship status, owed replies, approvals, meetings, open work and applications reach a turn only when a tool or lane happens to read them. Fast lanes such as the fit sweep answer constraint-bearing questions without them, and can even contradict them (D1).
3. **P1: voice-only words pollute Q's memory.** The B1 mirror stores the voice's promises and word fragments as Q messages (D3, D10). Later typed and spoken turns inherit them.
4. **P1: the interview has two drivers** (voice model and code steer), so it re-asks and flips values (D8). This is an owner decision (27 Oct, D86) and is flagged, not overridden.
5. **P2: the resume opening is template-quoted from the last fragment** and carries no account state (D9).
6. **P2: transcription.** No utterance coalescing (D10). Misheard words reach voice-side tools (D12).

## 4. Proposed fix direction (one Q; voice as I/O only)

1. **Route every live-line utterance through Q, with code, not the voice model, deciding.**
   - Port `duplex/routing.ts` to the live line: on each finished user transcript, the bridge creates the delegation itself. Only the closed small-talk set stays with the voice.
   - Drop the voice's discretion (`prompt.ts:133-149`). "Go ahead", "still waiting" and similar always reach Q. Q, holding the run state, answers truthfully, for example "nothing is running; starting it now", or it starts the re-run.
   - Replace "keep the conversation going" (`bridge.ts:382`) with one code-chosen progress line that asks no questions.
   - Remove "otherwise say it is coming up" (`prompt.ts:129`).
2. **Speak Q's words, not a paraphrase.**
   - Hand the voice Q's spoken line (`facts.fallback` or `said`) with "say exactly this, adding nothing". This is the duplex `ANSWER_INSTRUCTIONS`, which already exists.
   - Stop sending "Details for follow-up questions" and the request text into the speak instruction (`broker.ts:522`, `:573`). Follow-ups go back to Q.
   - Carry scope qualifiers in `mustSay` (for example "leaving out the ones already shown").
3. **One account-context assembly for every turn, typed or spoken.**
   - Add a firewall-filtered account digest to the situation header, built by code, as the person, for their actor only. It would hold: relationship status per counterpart (contacted, owes reply, meeting booked), pending approvals, upcoming meetings, running work, and open GateQ applications.
   - Make fast lanes honour it. Add `fitQuestion.excludeRelationships` (or a scope `CANDIDATES_UNTOUCHED`) read by the turn reader, so the sweep drops `own.relationships` instead of adding them.
   - Add a post-answer check: when the request carries an exclusion or constraint that the answer did not apply, Q says so instead of answering past it.
   - Use the same digest for the resume opening (replace `continuation.ts:73-91`) and the live context package.
4. **Q's memory holds only Q's decisions.**
   - Stop mirroring voice-only segments as role `Q`. If they are kept, store them as a separate `VOICE_ACK` kind that Q's context excludes.
   - Coalesce transcript segments per utterance before storing them.
5. **Interview (needs the owner's decision).** Either code owns the next question (the voice speaks the steer's ask only), or the voice owns it and the steer is limited to "saved / not saved" facts. One driver, not two.
