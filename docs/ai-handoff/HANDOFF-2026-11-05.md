## 7. Lessons that cost time (don't repeat them)

- Run `npx prettier --check apps packages docs` before every CI push. Merged handoff docs often fail it, and HANDOFF-LOG conflicts are common: resolve by keeping both sides.
- Whenever a page is added, run the route-coverage tests: `back-everywhere`, `destination-routes`, `manifest-page-coverage` and `app-routes`.
- A new `t()` string needs Arabic in `apps/web/src/features/i18n/catalog/sweep.ts`, then `node --experimental-strip-types scripts/i18n/generate-ui-text-source.mts`, then a q-core rebuild.
- Never push to CI with root tsc ≠ 0. Use `node --max-old-space-size=7168 node_modules/typescript/bin/tsc --noEmit -p tsconfig.json`.
- Use eslint and tsc with `NODE_OPTIONS=--max-old-space-size=6144` or higher (OOM otherwise).
- CI takes about 25–30 minutes; the test job is the long one. Schedule one check rather than polling.
- Child sessions' auto-mode classifiers refuse credential reads, production pushes and magic-link minting unless the owner approves **in that session**. Messages from this session don't count as approval. Do credential-dependent steps in the integration owner session, or have the owner approve in the child.
- `positionsAskOf` and the other regex reference rules conflict with the owner's "no keyword rules over people's words". Step 3 removes them.
- A new rule (the claim check) caused CI false positives on timestamps. Always run the full `pnpm test` for touched apps before merging.
