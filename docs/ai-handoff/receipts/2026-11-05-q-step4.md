## What changed

**Reader: TURN_READER v78** (`packages/q-core/src/prompts/tasks/turn-reader.v78.ts`). v78 keeps v77 whole and adds one WHAT WAS ASKED rule right after REFERENCES, so the cached prefix is unchanged. Everything in it is read by meaning, in any language:

- `answerKind`: CHAT, LOOKUP, FOLLOW_UP, ANALYSIS, COMPARISON or DOCUMENT. It is the heaviest work the turn asks of the answer.
- `parts[]`: `{ask, kind}`, one entry per separate thing in a compound ask, in order and self-standing. It is empty for a single ask.
- `remember`: `{fact}`, a fact to keep, said back in the second person. `fact` is null when it wouldn't read back plainly.
- `asksForChart` and `asksForWeb`: booleans.

Every field is lenient: a malformed value costs only that field, never the reading.

`prompts.lock` gains only `turn-reader/v78`; every earlier hash is unchanged. v77 is now DEPRECATED, and the active-version pins moved 77 → 78.

**Contract.** `QAnswerRequest` (q-runtime) gains `answerKind`, `askParts`, `rememberAsk`, `asksForChart` and `asksForWeb`. `answer.ts` passes them from the reading, and only when the reading has them.

**Validation and the neutral default.** `readAnswerKinds` checks every kind against the closed enum and drops unknown values. When the reader is absent (FAKE or scripted mode, or a failed reading), every lane takes its neutral default and never falls back to a word list:

| Lane                                                                      | Neutral default                    |
| ------------------------------------------------------------------------- | ---------------------------------- |
| Task class                                                                | the capability's own class         |
| Comparison handling                                                       | not a comparison                   |
| Parts note                                                                | none                               |
| Remember confirmation, chart line, web research for ADVICE, work products | none                               |
| Board save                                                                | none                               |
| Record audience                                                           | the reading's own tool (unchanged) |

**What reads the fields now:**

- **`answerTaskClass(request)`** no longer takes their words. COMPARISON maps to COMPARISON; ANALYSIS and DOCUMENT map to EVIDENCE_SYNTHESIS; the analytical question kinds are kept. The heaviest part of a compound ask wins.
- **Three comparison regexes are now `readAsComparison(request)`:** the named-card comparison, and the two single-company notes.
- **`askPartsNote`.** A compound ask's parts reach the answer first among the turn notes, so the bounded notes never cut them. They are listed in order and JSON-quoted as data, never as instructions. The note says to answer every part, and to say any part the facts don't settle is unknown.
- **`rememberConfirmation(request.rememberAsk)`** replaces REMEMBER_ASKED, its checks and the 15-regex pronoun swap.
- **`couldNotLineFor(gap, asksForChart, …)`** replaces ASKED_FOR_CHART.
- **`asksForWorkProducts(read.parts)`** is true for two or more ANALYSIS, COMPARISON or DOCUMENT parts. It replaces 6 regexes.
- **`savesToBoard`** reads `boardAsk` only; the save/keep word fallback is gone. **`asksNewWork`** is `teamJob`, or a DOCUMENT `answerKind` or part; the write/draft verb regex is gone.
- **`recordAudienceTool(read.askedAction)`** reads the v30 field; the RECORD_AUDIENCE word lists are gone.
- **`adviceOnCapitalQRecord`** is now a pure exported function on `asksForWeb`; NAMES_THE_WEB is gone. A web address still triggers research.

## Risks for the live check

- **Reader omissions.** Each lane now depends on the reader. If v78 leaves a field out, the lane takes its neutral default, never the old word guess. Three cases to watch:
  - "save that plan to my board" with no `boardAsk` is no save;
  - a deck-audience ask with no `askedAction` stays the company's hand (it is still prepared for approval, never executed);
  - "check the news" on ADVICE with no `asksForWeb` answers from the record.
- **Step 7 coupling.** `answerKind` is also the input step 7 needs (FOLLOW_UP for LOW reasoning; COMPARISON, DOCUMENT and ANALYSIS for MEDIUM).
