## What changed

**The level follows what the reader read** (`packages/model-gateway/src/q/index.ts`, next to `answerTaskClass`):

| answerKind (v78) | Reasoning | Policy key          |
| ---------------- | --------- | ------------------- |
| CHAT             | NONE      | `ANSWER_CHAT`       |
| LOOKUP           | NONE      | `ANSWER_LOOKUP`     |
| FOLLOW_UP        | LOW       | `ANSWER_FOLLOW_UP`  |
| COMPARISON       | MEDIUM    | `ANSWER_COMPARISON` |
| ANALYSIS         | MEDIUM    | `ANSWER_ANALYSIS`   |
| DOCUMENT         | MEDIUM    | `ANSWER_DOCUMENT`   |

- `answerReasoning(request)` reads `answerKind` and the kinds of `askParts` only. The heaviest wins; a tie in level is broken by a fixed kind order, so the key is deterministic. It takes no words, has no regex and no word list.
- No reading (FAKE or scripted mode, a failed reader), an unknown kind, or a capability other than ANSWER gives NONE with no key.
- `ANSWER_REASONING_V1` is the versioned code default.
- The index.ts edit is small: the function, the `base` request gains `reasoning` and `reasoningKey`, and one log field. The tool loop is untouched (Step 8's lane).
- The parallel side-field call ("extras") runs on `unthinking`, the base without a level. It runs beside the answer and must not become the slowest call.

**The routing config has the last word:**

- Contract (`packages/contracts/src/model/index.ts`): `ModelGatewayRequest` gains an optional `reasoningKey` (`^[A-Z][A-Z0-9_]{0,47}$`), a label the caller chose.
- Catalog (`catalog.ts`, `infrastructure/postgres-catalog.ts`): a routing policy gains `reasoningLevels`, a map from key to level. It is read through `to_jsonb(rp) -> 'reasoning_levels'`, so a service deployed before the migration still loads. A malformed map is caught to null and costs only the map.
- Gateway (`policy/eligibility.ts` `reasoningUnderPolicy`, `gateway.ts`):
  - the policy's level for the named key wins;
  - with no key, no map, or a key the map lacks (own properties only), the request's level stands;
  - the result applies to every attempt of the request, fallbacks and hedges included, and is on the span as `q.model.reasoning`.
- **Per-model guard:** a level above NONE reaches a provider only for a model the catalogue marks `supports_reasoning`; any other model is asked for NONE. All three dialogue and synthesis models (gemini-3.5-flash-lite, gpt-5.6-luna, gemini-3.5-flash) are marked true.
- The providers already map the level: OpenAI `reasoning.effort`, Gemini `thinkingLevel` (NONE becomes MINIMAL), Groq `reasoning_effort`.

**Migration** `20261231260000`:

- adds the nullable `reasoning_levels jsonb` with a shape check: an object, keys `^[A-Z][A-Z0-9_]{0,47}$`, and string values in NONE, LOW, MEDIUM or HIGH;
- writes the table above on the ACTIVE rows of NORMAL_DIALOGUE, EVIDENCE_SYNTHESIS and COMPARISON;
- has no DROP, no RLS or grant change, adds or retires no row, and changes no route.

It updates in place, following the hedge precedent (`20261207163000`). Bumping policy versions would strand later migrations that update by code.

**Streaming a lead sentence while reasoning runs: skipped, deliberately.**

- Neither Gemini nor OpenAI emits answer text before its thinking ends, so the only way to get a lead sentence is a second, unthinking model call.
- That sentence would reach the person before the step 6 claim check sees the answer it introduces, so it could state an unchecked figure or contradict the answer.
- The existing nameless holding line (owner-approved 2026-10-23) already covers the wait without making any claim.

## Bar

There are no live calls, so Q-IQ category scores and p50 latency can't be measured here. What is proven deterministically:

- each answerKind picks the right level;
- follow-ups and lookups stay at NONE or LOW;
- comparison and analysis get MEDIUM;
- the level reaches the provider request through the real Q answer seam and the gateway.

**For the integration owner's live Q-IQ:**

- The comparison and number categories should rise against step 6.
- Follow-up p50 should stay ≤ 2.5 s, since they run at NONE or LOW.
- If p50 rises, set `ANSWER_FOLLOW_UP` to `NONE` in the routing config. That needs no deploy.
