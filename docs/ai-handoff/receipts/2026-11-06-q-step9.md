## 1. Memory keeps who said it

**The defect, found.** HANDOFF-2026-11-01 defect 1 had two halves:

- The onboarding write (Q's category saved `user_selected`) was already fixed and tested (`apps/q-api/test/onboarding-integrity-1102.test.ts`).
- The memory half was still open. The memory Write Gate proves that a memory's **quote** is the person's own words. It never proved the **content** was. The content is the extractor's or tool's sentence, so:
  - "Invests in B2B SaaS companies", quoted from "We back B2B companies with recurring revenue", was recalled as `They said (date): Invests in B2B SaaS companies`.
  - A preference read the same way was recalled as `Preference (date): …`.
  - The situation assembler then typed every recalled line `truthClass: USER_CLAIM`.

**Failing test first:** `packages/q-knowledge/test/memory-provenance.test.ts` failed on the base renderer (two Q readings presented as stated), then passed after the fix.

**Fix.** All of it is deterministic code. No model judges provenance, and nothing reads a person's words for meaning.

- `packages/q-knowledge/src/memory/provenance.ts` adds `memoryTruthClass(item)`, derived from the row. It returns USER_CLAIM when either:
  - the write mode is `USER_CONFIRMED`, `AUTOMATIC_SYSTEM` or `ADMIN_VERIFIED`; or
  - Q's content occurs in the person's quoted words.

  Everything else is Q_INFERENCE. No column or migration is needed, because write mode, content and quote are already stored.

- `render.ts`:
  - Q's reading renders as `Q's reading — Preference (date), not their words: … ; their words: "…"`.
  - Only USER_CLAIM items keep `They said` / `Preference`.
- `q-specialists/src/situation/assemble.ts`: a recalled line carrying Capital Q's own "Q's reading" label is typed `Q_INFERENCE`. Every other line stays `USER_CLAIM`.
- **Deterministic check** `inferredPresentedAsStated(text, items)`: a Q_INFERENCE memory's content inside a sentence that frames it as stated ("you said", "your preference", "They said (", …) over Capital Q's own text. It is used in:
  - the unit tests (memo = rendered recall);
  - the Q-IQ integration test, over every reply and every system prompt.
- Writes still go only through the Write Gate. Nothing about the gate changed.

## 2. Search over the person's own past turns

- **Migration `20261231271900_q_runtime_message_search.sql` (additive):**
  - One GIN expression index: `to_tsvector('english', content)` on `q_runtime.conversation_messages`.
  - No column, no data change.
  - RLS, policies and grants are unchanged: RLS on, no policies, no client grants. Browser principals still read nothing.
  - It needs no `130_schema_guard` classification, because no table was added.
- **`messages.searchForOwner`** (q-runtime):
  - Tenant and owner come from the actor, and ownership comes from the join to `conversations.user_id`.
  - Left out: archived conversations, marked lines (20261110030000), superseded runs, and the current conversation.
  - Lexemes are parsed by Postgres and ORed, as in the knowledge lexical search. A question of only stop words matches nothing, never everything.
  - Results are ranked by `ts_rank_cd`, best first, bounded at 12.
- **pgvector is not used:** no embeddings exist for messages, and no embedding pipeline was added (as briefed).
- **Memory service (`recall`):**
  - Searches past turns only when the caller sets `ownConversationsAdmitted`, which comes from the run's Context Firewall plan (`planAdmitsOwnMemory`: the actor-wide `OWN_Q_CONVERSATION` scope for this very person). Authorisation is resolved before retrieval.
  - Searches only for a HUMAN actor.
  - Searches the utterance plus their last two earlier words in this conversation, so "Why?" still finds its topic.
  - A failed search is absent (unknown), never "none".
- **Rendering:** a past-turn section, `they said: "…"` (their words) vs `Q said: "…"`, labelled "not verified evidence".
- **Recall seam** (`model-gateway/src/q/index.ts`):
  - `QMemoryRecall.recall` takes `plan` and `earlierWords`.
  - It may return `{ text, ownWords }`; `recalledText()` reads either shape.
  - `ownWords` holds the person's **own** recalled words only, never Q's. They join the claim check's sources, so "You said your cheque is $750,000" is grounded by what they said last month.
- **One composition, `createMemoryRecall`** (q-knowledge), used by q-api's memory learner and by the Q-IQ world.
- **Q-IQ world** (`q-evals/src/runner/q-iq-world.ts`):
  - Composes the real memory service over the world's store, with the same past-turn search.
  - A case's prior conversations are stored as real conversations of the person: a run per person turn, Q's reply beside it, backdated by `when`.
  - Earlier cases' conversations of the fixture person are archived first, so each case has only its own history. This is harness hygiene: archived conversations are never searched, as in production.
  - No model is called to seed.
  - `CQ_Q_IQ_MEMORY=0` turns recall off, for the before/after.

## 3. Language is a communication aspect

- `note_preference` takes `{ aspect: "language", value: <BCP 47 tag> }`. It is quote-verified through the Write Gate, SESSION or LONG_TERM, and kept as `preference.communication.language` (or a session key) with a canonical tag (`QLanguageCodeSchema`). An invalid tag is refused.
- Consent works as for the other aspects:
  - a stated preference is consent by statement;
  - the learner's inferred PREFERENCE items are still withheld without consent.
- `communicationLanguageFromMemory` resolves long-term first, then this conversation's session preference, newest winning. `LoopMemory.language` carries it.
- q-api `languageOf`: their Settings language wins. Only where it is AUTO does a remembered long-term language apply.
- The tool description says that switching the whole app's language is still `set_q_language`.

## Known limitations

- `apps/q-api/src/composition/workforce/plan-job.ts` cites `Remembered: They said (date)` as "what you told Q". A `Q's reading — …` line now falls to its generic "what Q remembers" label. That is honest but less tidy. It is the step 10 lane's file, so it was left untouched here.
- Communication aspects the learner infers (the language included) are kept with no structured value, so they never change the profile or language. Only stated ones (`note_preference`) do. This is unchanged behaviour.
- The IC memo reads the mandate's taxonomy preferences, whose source the 1102 onboarding fix governs. Defect 4 ("(company record)" on mandate preferences) is a separate item and not touched here.
- Past-turn search is lexical only. A paraphrase with no shared lexeme ("what did I turn down?" for "pass") misses until message embeddings exist.
