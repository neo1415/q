# Q latency baseline, 2026-10-15 (lane S)

These are measured numbers only. Wherever n < 100, the p95 is left out on purpose. All sources are read-only, and collecting them made **no model calls**.

## Sources and method

- **DB.** Supabase `vcohxiqsmnkzxnvawgri`, through the read-only management query, for the 7 days ending 2026-10-15.
  - `ai_ops.model_usage` gives the latency, model served, cost and failure of every gateway call.
  - `q_runtime.runs` and `q_runtime.run_events` give run wall time and the first `q.stage.changed` / `q.message.completed` event.
  - `q_runtime.conversation_messages` was used only to classify asks; no content appears here.
- **q-api logs.** Railway deployment `3cc99168` (commit `d2de6697`) and the ten prior q-api deployments of 2026-10-13 and 14. Lines used: `request timing`, `q fast navigation resolved`, `voice turn timed`, `q fast lane`, `q answered …`.
- **Client.** The sandbox is in the US and the service is in eu-west, so client RTT includes about 150 ms of transatlantic network. Scripts: scratchpad `navbench.mjs` and `s-readbench.mjs`. Accounts: seed investor `investor.savanna-seed` and founder `founder.maji-loop`.
- **Run time** is `completed_at - created_at`. Queue time to `started_at` has a p50 of 150–230 ms for every lane.

## Not measured yet

These need the browser driver (`scripts/handoff/live/*`) and, for Q turns, paid model calls. They wait for lead budget approval.

## What the numbers say (inputs to slices 2–5)

1. The ordinary generation answer (p50 10–15 s) is the largest gap. Nothing is visible until the full synthesis ends, so streaming the first validated text is the biggest perceived win (slice 3).
2. Classification-only turns take about 2 s, and about 0.8–1.0 s of that is one FAST call that code could replace for strict, read-only asks. Examples are pure fit ranking ("top 3 companies against my mandate") and navigation through the run path (slice 2).
3. Speculative classification is spent on turns that code answers. Removing it is a cost and contention fix more than a latency one.

## 6. Live Q turns, 2026-10-15 (paid, owner-approved)

- **Calls and cost.** 24 text turns made 104 gateway calls: 44 FAST_CLASSIFICATION, 36 NORMAL_DIALOGUE and 24 STRUCTURED_EXTRACTION (post-answer memory). The estimated cost is **$0.165**, from `ai_ops.model_usage` over the window; this is an upper bound.
- **How it was measured.** Driver `qlive.mjs`, three seed accounts (2 investor, 1 founder). "First text" is the first poll, at a 250 ms interval over about 170 ms RTT, that sees the Q message. The text is not streamed, so first text ≈ full answer minus finalisation.

| ask class                                                                |   n | model calls (FAST / NORMAL)   | first text ms  |
| ------------------------------------------------------------------------ | --: | ----------------------------- | -------------- |
| code lanes (pleasantry, own mandate)                                     |   3 | 0 / 0                         | 1167–2391      |
| page navigation through a run ("go to capital", "take me home")          |   5 | 1–2 / 0 (speculative, unused) | 534–1900       |
| fit ranking via skim ("top 3 companies against my mandate", "rank…")     |   4 | 2 / 0                         | 1533–2636      |
| investor discovery for a founder ("which investors fit us?")             |   1 | 2 / 0                         | 1533           |
| **basic fact about a named company** (stage, founders, "what does X do") |   6 | 2–3 / 3–4                     | **7970–12690** |
| company overview / risks ("tell me about X", "risks with X")             |   4 | 2–3 / 3                       | 14184–16481    |
| founder readiness / next steps                                           |   2 | 2 / 1                         | 8891–9450      |
| comparison of two named companies against the mandate                    |   1 | 2 / 3                         | 25195          |
| "open Q Daily" as a founder (fell to the model; 5 NORMAL calls)          |   1 | 1 / 5                         | 14184          |

With n this small these are ranges, not percentiles. Findings:

- **Basic facts about a named company take 8–13 s**: one plan call, one tool round and one composition call, after 2–3 classifications. This is the largest avoidable round-trip cost.
- **"Show my top 3 companies … and explain why"** now goes to generation (2 FAST + 1 NORMAL, 5.9 s), while the same ask without "explain why" is code (1.6 s).
- Voice sessions were not run: the realtime session needs a browser with a microphone. They wait for the browser driver.

## 7. First streamed text over the run SSE stream (paid)

- **Driver.** `s-sse.mjs` opens `GET /v1/q/runs/:id/events` right after `POST /v1/q/runs`. n = 5 generation-class asks, seed investor.
- **Cost.** 45 gateway calls, $0.103 (estimate). The running total for this lane round is **150 calls, $0.27**.

| ask                                          | first stage | first delta (chars) | message completed |
| -------------------------------------------- | ----------: | ------------------: | ----------------: |
| Tell me about Baridi                         |        1603 |         11123 (139) |             18683 |
| What are the risks with Ledgerfold?          |         888 |          8305 (134) |             16846 |
| Who are the founders of Ledgerfold?          |         836 |           7937 (78) |             10107 |
| What should I ask Maji Loop's…               |         951 |          7753 (163) |             16420 |
| Compare Ledgerfold and F2 against my mandate |         813 |          9138 (233) |             19189 |

What this shows:

- Sentence streaming already exists. The composing round's guarded sentences reach the browser **2–10 s before completion**.
- The first sentence still waits **7.7–11.1 s**. Before it come about 2 s of readers and **1–2 tool rounds of NORMAL_DIALOGUE (~1.5–2.5 s each)** that only fetch the named company's records.
- The next win is to read a company the person named by name ahead of the model, the way the on-screen company is already read. That removes those rounds; it does not stream harder.

## 8. Record-page answers over SSE (paid, n=4)

- **Setup.** Investor on Ledgerfold's page: `screen.route=COMPANY`, sent both with and without `subjects`. Revision `85b08f21`.
- **Cost.** 23 calls, $0.041. The lane total so far is 173 calls, $0.31.

| ask                                 | first delta |   completed | model rounds before composing                  |
| ----------------------------------- | ----------: | ----------: | ---------------------------------------------- |
| What does this company actually do? |   3924–5737 |   6517–8218 | 1–2 FAST, then the composing NORMAL round      |
| What are the main risks here?       |   7038–9619 | 18452–20095 | 1 FAST + 2 NORMAL tool rounds (1.7–2.0 s each) |

Two problems show in the q-api log for one risks run (`69e50e45`):

- **The model searched for a company again** (`company.search`, then `company.get`) even though the on-screen company had already been read. The turn reader had marked the question `aboutNamedOther=true`.
- **The answer phase made 303 of the run's 329 DB round trips.**

Sentence streaming and barge-in (the provider drops the think request and the turn's signal aborts) already exist for voice (`apps/q-api/src/voice/think.ts`). What remains is the work done before the composing round, not streaming.
