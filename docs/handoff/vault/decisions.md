# Capital Q — decisions

- 2026-09-15 — Realtime voice uses the ElevenLabs Speech Engine as transport only; the Q API hosts the voice WebSocket and every spoken turn takes the same `say` / Q-run path a typed one does (ADR 0010). Reason: one Q, one authority, no voice database.
- 2026-09-15 — The provider conversation id is bound server-side to the resolved actor and thread before a voice credential is returned; unknown or reused ids are closed. Reason: speech is never identity (TM-VOICE-01/02).
- 2026-09-15 — Q's voice presence is the Q mark in a level-driven ring, never an orb or HUD. Reason: doc 18 §33; calm, institutional product.
- 2026-09-15 — Interview moves (question-for-Q, pause, resume, thinking) live once in `@capital-q/onboarding/interview` and are shared by the typed and spoken threads. Reason: a sentence must mean the same thing whichever way it arrives.
- 2026-09-15 — Committing an answer retires other pending proposals for that step. Reason: an old proposal must never linger as an invisible overwrite.
- 2026-09-15 — Q conducts the interview through a model-driven turn (INTERVIEW_CONDUCTOR) whose readings deterministic code validates against the step's own kind and options before anything is recorded; material values are held until the person confirms. Reason: a per-step scripted parser could not hold a conversation ("here's what I understood" loops); the model may talk, only code may write.
- 2026-09-15 — While the person talks with Q, the interview screen is a full-screen dark stage with the Q mark and Q's words, options only when the live step is a choice; typing is a toggle, not the base. Reason: voice was bolted onto a chips-and-composer screen and felt like it.
- 2026-09-15 — Model Gateway rotates across GROQ_API_KEY, GROQ_API_KEY_2..4 on 429 with a 30 s cooldown per key. Reason: a single free-tier key rate-limited mid-interview.
- 2026-09-15 — A live interview turn renders a voice-sized charter (Q_SYSTEM_VOICE) and a compact open-steps list, and NORMAL_DIALOGUE falls back across several Groq models with the gateway moving to the next model on a 429. Reason: Groq's free tier is 8k tokens a minute per model; a 4.9k-token turn made the second turn in any minute fail.
- 2026-09-15 — Q's conduct in a conversation (manner, tangents, sabotage warnings, navigation, lookups) is proposed by the model and enforced by code: warnings are counted in code, destinations are a fixed list, lookups become questions for Q's own research tools. Reason: the model may talk; only code may act.
- 2026-09-15 — The Speech Engines run eleven_v3_conversational in expressive mode with scribe_realtime and an ASR keyword list for West African names and places. Reason: laughs and sighs need v3; a recogniser mis-hears unknown names far more than accents.
- 2026-09-15 — Google Gemini serves CONFIDENTIAL work in this environment (demo posture, human operator decision); the provider review stays UNREVIEWED and the ceiling is reverted before real customer data. Reason: a demo must not be gated by one provider's free-tier minute.
- 2026-09-15 — An interruption pauses Q; it never discards Q's words or cancels a research run. Reason: "if it gets interrupted it should pause, and go on when asked" — a person does not restart a sentence.
- 2026-09-15 — Sign-in lands on arrival (/welcome) for a person Capital Q knows nothing about; Q introduces itself, learns the name and infers the journey. Reason: Q first, not a menu.
- 2026-09-15 — Bright Data is the second research provider: LinkedIn person/company pages by URL through its datasets (the only thing that leaves is the URL the person gave), and Google search plus page reading through named zones when configured. Reason: the public web alone cannot see a founder's or investor's LinkedIn presence; the provider claims compliance and takes only a URL.
- 2026-09-15 — Gemini leads NORMAL_DIALOGUE, EVIDENCE_SYNTHESIS and STRUCTURED_EXTRACTION for the demo, Groq follows. Reason: the operator's choice; Gemini's free tier is bounded per request-minute rather than by an 8k token-minute.
- 2026-09-15 — The Deepgram Voice Agent is the default voice transport; Q remains the brain through an OpenAI-shaped think endpoint on the Q API guarded by a per-session bearer. Reason: ElevenLabs minutes ran out; Deepgram's agent needs no worker infrastructure and bills from a starting credit; LiveKit stays the path to backchannels and noise cancellation.
- 2026-09-16 — Provider privacy class for google is ENTERPRISE_CONTRACT in this environment only (migration metadata says demo_posture, actual UNREVIEWED). Reason: eligibility derives a ceiling from the provider row, not the model row, so the earlier model-level posture never made Gemini eligible; revert before real customer data.
- 2026-09-16 — A destination Q names is followed after Q has finished saying it, never at once. Reason: the goodbye and the warning are part of the handoff; cutting them made transitions feel broken.
- 2026-09-16 — A long turn is never silent: a spoken beat at 3.5 s, stream keep-alives, and a growing status note. Reason: "there needs to be some kind of state or buffer instead of just waiting for it forever".
- 2026-09-16 — A person with no organisation acts under one well-known personal tenant (`PERSONAL_BOOTSTRAP_TENANT_ID`) on the voice routes only. Reason: the actor schema already allows a personal context, but every ledger row needs a tenant; the arrival conversation was refusing exactly the people it exists for. Revisit as an ADR before other routes accept it.
- 2026-09-16 — Public research runs every configured index in a row behind a short memory; "refresh" words bypass the memory. Reason: one rate-limited index must not cost the answer, and the same page should not be paid for twice in one conversation.
- 2026-09-16 — Q reads sounds, endings and destinations deterministically before the model. Reason: a cough is not a turn and "take me to Discover" is not a question; neither should depend on a model call.
- 2026-09-16 — A provider's INVALID_REQUEST falls through to the next candidate. Reason: Gemini 3 rejected every tool follow-up that lacked its thought signature; a request one provider cannot take is that provider's quirk, not the person's problem.
- 2026-09-16 — A spoken "make me visible" is executed by Q after one confirming question. Reason: the spoken yes binds to the exact payload (Prepare → Recommend → Approval → Execute) and the platform's visibility API does the work; Q never flips the flag itself.
- 2026-09-16 — A public page is kept only when it names something distinctive about the subject, checked deterministically before evidence, model or gate. Reason: the first live read returned an unrelated apartment building for an uncommon company name and the model reported it accurately; a missing understanding is a gap, a wrong one is a lie with a citation.
- 2026-09-16 — Observed public signals (presence.signal.*) are excluded from every ranking feature by a named list. Reason: they are Q's reading of somebody's posts; a founder must not rank higher because a model liked how they write (doc 19 §204.8/§204.9).
- 2026-09-16 — Investor organisations have the same two visibility states as companies, and becoming visible exposes the declared profile only. Reason: doc 19 §44 needs a column to read for founder-facing discovery, and §204.9 forbids private investor behaviour reaching a founder.
- 2026-09-16 — Untrusted content has its template braces neutralised at the fence. Reason: a Wikipedia page's own "{{...}}" markup was tripping the unrendered-token guard and failing whole turns.
- 2026-09-16 — Discovery candidates are selected cross-tenant on the declared visibility column. Reason: network_visible means visible to authenticated participants (ADR-001) and every organisation has its own tenant; scoping to the caller's tenant made the switch do nothing.
- 2026-09-16 — Founder-facing discovery ranks on the declared investor profile only, and says so on every slate. Reason: an investor's mandate is investor-private and doc 19 §204.9 makes it release-blocking that it must not shape a founder's view.
- 2026-09-16 — A platform lookup that returns nobody triggers public-web research deterministically, in code. Reason: a small model reliably searches Capital Q, finds nothing and stops; the person then reads "I have no information" about a company with a Wikipedia page.
- 2026-09-16 — Tool results are named as answerable material in both the environment notes and COMPANY_ANALYST v2. Reason: Q was fetching public sources and then refusing to use them, correctly, because every instruction said to answer from the supplied facts alone.
- 2026-09-17 — An answer whose text was delivered before its structured object was refused stands as the answer; the run completes without the structured extras. Reason: nothing said can be unsaid, and "I hit a snag, ask again" after a full answer reads as Q contradicting itself.
- 2026-09-17 — A malformed citation label is dropped before the schema, never a reason to refuse the answer. Reason: the specialist dropped unresolvable labels after the schema anyway; the schema refusal only cost the prose.
- 2026-09-17 — The demo stack is started outside the assistant's process tree (WMI) and refuses a half-local, half-hosted Supabase configuration. Reason: the Claude app's self-update killed the stack twice, and a mixed configuration fails in ways that look like everything else.
- 2026-09-17 — Approved MCP tools enter the Tool Registry only as source-controlled definitions with Capital Q's own schemas and authorize step (`@capital-q/q-connectors`); the MCP server façade is off unless `Q_MCP_SERVER=enabled`. Reason: doc 12 §34: MCP authorization does not replace Capital Q authorization, and REST/SSE stays the primary boundary.
- 2026-09-17 — The embedding runtime is deployed as a Render private service, not swapped for a hosted embedding API. Reason: confidential document text must not leave Capital Q's infrastructure, and a different model changes the vector space every chunk was indexed in.
- 2026-09-17 — A closing sentence that only promises to act is removed from an answer and never streamed. Reason: "Give me a moment to look that up." at the end of a finished answer was heard as work Q then never did.
- 2026-09-17 — An upload step answered aloud is set aside, not re-asked; the person is told where the upload lives. Reason: a voice cannot attach a file, and the same question was asked three times.
- 2026-09-17 — Hosted Supabase migrations are pushed over the session pooler with sslmode=require (pnpm db:push). Reason: the direct host is IPv6-only and unreachable from this network, and the CLI fails auth on the pooler without TLS named.
- 2026-09-17 — ADR 0011: meaning is read by a model into a closed schema; code validates, holds, confirms and executes. No new word lists to decide what a person meant. Reason: three demos of regex patches; the interview already worked this way and the failures were validators dropping readings silently.
- 2026-09-17 — Profile changes are the first real Q action (company.profile.update, CONFIRM_REQUIRED): analyst reads the request quoted from the person's words → answer seam notes it → proposer → Approval Engine → yes on screen or aloud → companies context writes. Reason: the sanctioned Prepare→Recommend→Approve→Execute path existed with no definition in it.
- 2026-09-17 — Analyst prompt promoted to v3 (same template, wider result schema); environment notes bound 2,000 → 2,600 chars. Reason: a schema is part of what a version pins; the profile instruction travels as a platform note rather than a template edit.
- 2026-09-17 — ADR 0012: conversations are listed, titled, reopened from the URL and archived; memory lives in `q_knowledge.memory_items` behind a deterministic gate (quote in the person's USER turns, hash dedupe, supersede by key, server-internal RLS); Q learns after each run through MEMORY_EXTRACTOR, detached from the answer; recall enters analyst v4 and conductor v3 as untrusted text. Reason: doc 13 §40 / doc 14 §55-§61 were unbuilt; a refresh lost the thread and nothing survived to the next session.
- 2026-09-17 — A reply to a closed question Q asked is read by DECISION_READER (yes/no/unrelated + verbatim remainder); the word list is only the fallback when no model answers. Reason: "Approved." fell through the regex into a run that claimed an approval was noted.
- 2026-09-17 — The person's own name is `person.profile.update` (CONFIRM_REQUIRED, self only), never a company field and never a word list. Reason: "change my name from Daniel" was refused and "call me John" stalled.
- 2026-09-18 — Hard eligibility (CQ-REC-001) is a tri-state, versioned pure policy inside `@capital-q/discovery` (`eligibility.v1`: ELIGIBLE / INELIGIBLE / UNDETERMINED), reading only owning-context query ports (Companies, Taxonomy, Investors, Network, Permissions). Reason: doc 19 §12–§13 and DMR-008/009; a FAIL outranks an UNKNOWN and an UNKNOWN never becomes a FAIL, so missing data lowers certainty and never means "poor company".
- 2026-09-18 — Marketplace participation is read only through `marketplaceParticipationOf` in the Companies context; `marketplace_ready` is the single eligible readiness state and everything else fails closed. Reason: PADL #58 makes readiness a Companies-owned gate distinct from `network_visible`; nothing writes `marketplace_ready` yet, so discovery through eligibility is empty until the readiness packet exists, and that is the honest state.
- 2026-09-18 — Only HARD_EXCLUSION is a hard rule: constraint importance HARD_EXCLUSION (operator names the excluded set) or a taxonomy preference with `isExclusion` from a `user_selected`/`admin_curated` source. MUST, AVOID, the cheque range and `custom.text` are never eligibility. Reason: the investors module and the DB comments already say so; cheque max below total raise is a partial ticket, not a mismatch.
- 2026-09-18 — A hard exclusion on a dimension no canonical company field can answer (red flags, attributes, declared sector codes) yields UNDETERMINED with the dimension named, never a silent pass and never a fill-in from a document, a memory or a model. Reason: the rule is real and the fact is missing; §17 of the packet.
- 2026-09-18 — Marketplace readiness is a Companies-owned, policy-derived state (`marketplace-readiness.v1`: not_assessed → requirements_outstanding ⇄ marketplace_ready) that nobody names directly: a founder asks for an assessment, the policy decides, transitions are audited and published. Reason: PADL #57/#58; a switch a client can flip is not a readiness assessment.
- 2026-09-18 — Verification is a claim-specific seam (`VerificationClaimsPort`) whose production adapter answers "unavailable"; no admin or manual "mark verified" path exists and none was invented, so no production company can become marketplace-ready until a Verification bounded context exists. Reason: doc 13 §24 and doc 25 §62 defer the provider while preserving the state contract; faking a verified company would be a trust bypass.
- 2026-09-18 — The only other verification implementation is a synthetic seam under `@capital-q/companies/dev` that refuses non-local environments and non-loopback databases and labels every transition SYNTHETIC_LOCAL_FIXTURE; `pnpm dev:marketplace-ready` uses it but never flips the founder's visibility choice. Reason: the Recommendation wave needs one legitimately ready local company; disclosure stays the founder's decision.
- 2026-09-18 — Withdrawing network visibility reassesses readiness in the same transaction; publishing never makes a company ready by itself. Reason: readiness is not an irreversible boolean and must not widen disclosure.
- 2026-09-18 — Structured candidate generation (CQ-REC-002) is one generator, `STRUCTURED_MANDATE` / `structured-mandate.v1`, inside `@capital-q/discovery`: a UNION of independent stage, geography and taxonomy retrievals over the discoverable projection, deduplicated by canonical company id with every reason kept, ordered by id, then gated by REC-001 in one batch; only ELIGIBLE leaves, UNDETERMINED is counted, never promoted. Reason: doc 19 §22–§23 and §36–§37; an AND-filter would let one unknown field empty the pool, and match count is not a rank.
- 2026-09-18 — The cheque dimension is a typed seam that reports NOT_COMPUTABLE. Reason: the capital objective is organisation-internal and its disclosure-safe projection is a later contract (capital.md); reading a private raise target into investor retrieval would breach the private-data firewall, and REC-001 already refused "max cheque ≥ total round".
- 2026-09-18 — Taxonomy retrieval honours the reference hierarchy (a preferred node reaches its descendants, own reason code) and treats the geography `global` node as unrestricted (no signal). Reason: the taxonomy query port already exposes `listDescendants`; "anywhere" must not match everyone.
- 2026-09-18 — The integration baseline runs on a reset local database; the eight remaining failures (gateway routing/ceiling, orchestrator public-run/tools, four company-intelligence evals, the PROVIDER_MISROUTING gate) trace to migration 20260921 demo Google posture contradicting tests scripted for the reviewed posture. Reason: realigning them is Q/gateway test work; changing product posture or eval invariants inside a Recommendation packet was refused.
- 2026-09-18 — Migration `20260921090000_demo_google_provider_posture.sql` (and the ceiling raise in `20260919`) is classified **C**: it contradicts the locked provider privacy policy (doc 13 §57.2, doc 15 §62: free Gemini is not eligible for private customer data until reviewed; config's deployment environment is not a security boundary). Corrected forward by `20260926090000_restore_reviewed_google_posture.sql` (google → UNREVIEWED, Gemini ceilings → PUBLIC); the applied migrations were not edited. Reason: the gateway derives the ceiling from the provider class, so the relabel cleared confidential customer material for an unreviewed free tier in every environment, hosted included. The demo intent survives through `20260920` (Gemini preferred wherever eligible, i.e. PUBLIC work); a reviewed paid tier is the route to a higher ceiling, never a data relabel.
- 2026-09-18 — Q/gateway fixtures were realigned only where an approved, privacy-neutral change had made them stale: the Gemini-first routing preference (`20260920`), the tools-first SYSTEM note (`1e1c4e1`), the company-specialist scope reader (analysis-verb phrasing) and the qwen model row (`20260918`, pgTAP 320 counts). No sensitivity, expected provider or PROVIDER_MISROUTING expectation was moved to make a test pass. Reason: an eval that asserts the route for CONFIDENTIAL data is a regression guard for the firewall, not a fixture.
- 2026-09-18 — A disclosure policy's lifecycle has one clock: `created_at`, expiry validation, `revoked_at` and status evaluation all read the injected `DisclosureClock`; PostgreSQL's `now()` is never a stamp for these rows, and the DB constraints (`revoked_at >= created_at`, `expires_at > created_at`) stay as defence in depth. Reason: two clocks made revocation racy under host/DB skew; sleeps or tolerances would have hidden the race and handed a grace period to revoked or expired grants.
- 2026-09-18 — Semantic candidate generation (CQ-REC-003) is `SEMANTIC_MANDATE` / `semantic-mandate.v1` inside `@capital-q/discovery`, a sibling of the structured generator, merged by canonical company id into `hybrid-candidate-pool.v1` with both provenances kept. Reason: doc 19 §22–§26 asks for independent high-recall generators; similarity is retrieval provenance for the ranker, never a fit, a match, a probability or a threshold.
- 2026-09-18 — The company investment representation (`company-investment-representation.v1`) is built only from the fields the Discover slate already shows an investor (canonical name, short description, stage, headquarters country, ACTIVE canonical taxonomy); business model, customer type, raise and traction are omitted until a canonical, discovery-safe field exists. Reason: the input type has no field a private source could fill, so founder-private memory, conversations, documents, evidence and raw research cannot be embedded by construction; inventing the missing lines from private material is exactly what the generator must not do.
- 2026-09-18 — Recommendation vectors live in their own server-only `recommendation` schema (representations + embeddings, immutable, superseded on change, cascade with their canonical row), not in `q_knowledge.embeddings`. Reason: that store keys every vector to a chunk of a private document; a marketplace projection does not belong in Q's private index. Exact scan under a configuration prefilter, like q_knowledge, until measured volume says otherwise.
- 2026-09-18 — The nearest-neighbour query joins current discoverability (`core.companies` active + network_visible/public_external) on every run and REC-001 decides the rest; vectors are never deleted to enforce privacy. Reason: a stale vector must never outrank a current privacy or readiness change, and deletion is not a permission mechanism.
- 2026-09-18 — The investor mandate representation includes the declared narrative (`raw_mandate_text`) and positive intent only; hard exclusions and AVOID never enter the text. Reason: a "never" is REC-001's authority and a hidden negative vector is not policy; a soft avoidance is not a retrieval signal.
- 2026-09-18 — DEMO_PROVIDER_ROUTING_FOLLOWUP stays open: synthetic/demo-safe Q traffic should later be allowed to use the preferred cheap/free provider without globally reclassifying that provider for real confidential customer data. Not a REC-003 blocker: semantic recommendation uses the local Qwen embedding runtime only.
- 2026-09-18 — Recommendation features (CQ-REC-004) are a frozen, validated registry `recommendation-features.v1` inside `@capital-q/discovery`: six V1 definitions (eligibility gate reference, declared stage/geography/taxonomy/cheque fit, semantic mandate similarity), each with group, type, allowed contexts, source classes, canonical sensitivity, missing policy and description. `registry.featuresFor(mode)` is the ranker's only way in; every V1 feature allows INVESTOR_DISCOVER only and any other context fails closed. Reason: doc 19 §145–§146 asks for the allowlist as code, not a wiki; default is not allowed.
- 2026-09-18 — Missingness is first-class: MISSING and NOT_APPLICABLE carry bounded reasons and never a zero; cheque stays `CHEQUE_NOT_COMPUTABLE`; semantic similarity is `SEMANTIC_NOT_RETRIEVED` unless REC-003 retrieved the company; a company with only Q-proposed classifications is taxonomy-unknown, not a non-match. Reason: doc 19 §92 — unknown stays unknown; a reader (REC-005) must never impute.
- 2026-09-18 — The founder-private ranking firewall is structural: feature computation reads typed projections tagged with their source class; a definition names the classes it accepts; a projection of any other class yields `SOURCE_NOT_AUTHORISED` and a scope-violation metric; the private classes are not in the vocabulary at all; the boundary guard holds `src/features` to the eligibility list. Reason: DMR-023/DMR-024 and doc 19 §42 require exclusion by construction, not by discipline.
- 2026-09-18 — Feature snapshots live in `recommendation.feature_snapshots`: one CURRENT row per investor organisation, mandate, company, context and schema version; a validated bounded jsonb payload in registry order; sha256 fingerprint over inputs and values (never computedAt); identical fingerprint reused, changed one supersedes; immutable; RLS on, no policy. Mandate-derived values are CONFIDENTIAL and the artifact inherits its highest class. Reason: doc 19 §147 V1 feature store in PostgreSQL, REC-006 needs historical reproducibility, and a derived artifact never downgrades its source sensitivity.
- 2026-09-18 — The V1 ranker (CQ-REC-005) is `DETERMINISTIC` / `deterministic-ranker.v1` bound to `ranking-config.v1`, requiring `recommendation-features.v1`, INVESTOR_DISCOVER only. It is pure over REC-004 snapshots and a config: no database, model, randomness or clock. Reason: doc 19 §108/§110 — V1 is inspectable rule/feature ranking behind a boundary a learned ranker can later implement.
- 2026-09-18 — `ranking-config.v1` is INITIAL_HEURISTIC_UNCALIBRATED: stage, geography, taxonomy and semantic similarity at equal weight 1; geography COUNTRY 1 / REGION 0.75 / NO 0; taxonomy EXACT 1 / DESCENDANT 0.75 / NO 0; stage MATCH 1 / NO 0; semantic (s + 1) / 2; cheque inactive (not computable); the eligibility gate never weighted; no minimum-fit threshold; tie-break score then company id, unscored last. Reason: no ADR or outcome data fixes weights (doc 19 §53); the simplest transparent baseline, replaced only by a new config version.
- 2026-09-18 — The internal score averages only the factors that are PRESENT (Σ normalized × weight ÷ Σ weight of present factors); MISSING / NOT_APPLICABLE are excluded, never zero; a candidate with none present is unscored, not poor; coverage is a diagnostic, never a penalty in v1. Reason: doc 19 §92 missingness and §51 — insufficient evidence lowers confidence, never fit.
- 2026-09-18 — The ranker fails closed on any incoherent input (context, tenant, investor, mandate or version, company, schema, unregistered / other-context / GateQ feature, feature version, ineligible or false gate) and re-verifies each snapshot's fingerprint, so a tampered value or client-supplied score cannot be ranked. A config must account for every registry feature in its context as a factor or an explicit inactive entry. Reason: REC-004 is the feature authority; the ranker must not reach around it or accept anything it did not produce.
- 2026-09-18 — Found by REC-005 testing, not fixed in it: REC-001 applies a declared hard exclusion against every ACTIVE company classification, including `q_inferred`, contrary to ADR 0006 (an unconfirmed candidate is not canonical). The feature layer and ranker already ignore undeclared sources. The fix changes eligibility semantics and needs `eligibility.v2`; tracked as a separate task.

- 2026-09-18 — Fixed as `eligibility.v2` + `structured-mandate.v2` (commit d0893d4): hard exclusion and structured taxonomy/region retrieval read declared company classifications only (`user_selected`, `admin_curated`); a company with only undeclared rows in an excluded vocabulary is UNKNOWN → UNDETERMINED, never PASS or FAIL. The source filter lives in the pure policy (versioned where the decision is) and, for retrieval, inside the Taxonomy SQL (`listCurrentByNodes(..., assignmentSources)`) so undeclared rows cannot consume the bound. Reason: ADR 0006 point 5 and the Context Firewall — a Q inference must not silently change investor-facing discoverability.

- 2026-09-19 — Recommendation slates (CQ-REC-006) are derived, versioned, immutable rows in `recommendation.slates` / `slate_items`: one CURRENT and one BUILDING per (investor organisation, ACTIVE mandate, context) via partial unique indexes; identity, versions and published content frozen by trigger; lifecycle BUILDING → CURRENT | FAILED, CURRENT → SUPERSEDED | INVALIDATED | EXPIRED; items insertable only while BUILDING and never updated; RESTRICT references to the ranked feature snapshot and the company; RLS on, no policy. Reason: doc 19 §62–§65 — readers see an old valid slate or a new complete one, never a partial set, and history stays interpretable.
- 2026-09-19 — A slate's generation fingerprint is sha256 over the key, every pipeline version and the ranked items' snapshot fingerprints — never a time, an id or a diagnostic count; an unexpired CURRENT slate with the same fingerprint makes a rebuild a no-op. Publication is one transaction that supersedes the previous CURRENT under row locks. Reason: reproducibility and idempotent refresh without a second source of truth.
- 2026-09-19 — Refresh work coalesces through one `refresh_requests` row per key with a monotonic request sequence (claim takes everything so far; a request landing mid-build reopens the row and gets one more message); pgmq (`recommendation-refresh` / `-dead`) carries bounded jobs of identifiers, reason, priority and sequence only. No new queue provider, service or env: the worker reuses its runner and the local embedding runtime's existing variables. Reason: pgmq delivers and retries but cannot coalesce or dedupe; the row does both.
- 2026-09-19 — Invalidation is lifecycle only: a material safety change (company withdrawn from discovery or the marketplace, a HARD_EXCLUSION mandate change, a closed mandate, a revoked company disclosure) marks the served slate INVALIDATED at once and asks for a HIGH rebuild; ordinary changes ask for a NORMAL rebuild while the old slate keeps serving. Reason: doc 19 §150 — a stale slate must never show what a declared rule now forbids, and a rebuild is a new slate, not an edit.
- 2026-09-19 — The reader re-runs REC-001 for the requesting actor on every page (one batch) and withholds what is no longer ELIGIBLE; the cursor is an opaque (slate, rank) position and never authority (a forged, stale or another investor's cursor is refused alike, 400, no hint); a SUPERSEDED slate keeps serving inside its expiry so a client mid-scroll keeps one ordering; an invalidated or expired slate restarts with SLATE_RESTARTED; nothing internal (score, snapshot, provenance, missingness codes) reaches the DTO. Reason: doc 19 §65 / doc 20 §80 stable keys plus the Context Firewall — what a slate stored is an ordering; whether a company may be shown is decided now.
- 2026-09-19 — A background build acts as a human member of the investor organisation (the mandate's creator with an active membership) because the disclosure evaluator denies every non-human principal; the read-time guard re-checks for the real requester. An organisation-level disclosure principal is a follow-up. Reason: a SYSTEM actor would fail INVESTOR_DISCOVERABILITY for every company, and changing the permissions evaluator is outside REC-006.

- 2026-09-20 — DEMO_PROVIDER_ROUTING_FOLLOWUP is CLOSED by implementing doc 15 §62's first clause rather than by moving a ceiling: `ModelDataPosture` (REAL_CUSTOMER | SYNTHETIC_DEMO) is a request-level routing fact, orthogonal to SensitivityClass and never a substitute for it. Under an attested SYNTHETIC_DEMO posture `planRoute` skips the model and provider privacy ceilings and records `ELIGIBLE_SYNTHETIC_DEMO`; no `ai_ops` row changes (google stays UNREVIEWED, Gemini ceilings stay PUBLIC) and no migration exists. Reason: §62 says free inference may be used aggressively for synthetic data and development while confidential customer information needs an approved provider — the gateway could express only the second half, so a demo of invented companies could reach only the rate-limited reviewed provider.
- 2026-09-20 — The synthetic-demo attestation needs four independent conditions and no single one decides: an operator opt-in (`CQ_SYNTHETIC_DEMO_ROUTING`, default off), `CAPITAL_Q_ENV` in {local,test}, a loopback database, and a per-request declaration from server code. No HTTP DTO carries the posture, so a browser cannot declare it; without an allowance a declaration is inert and the strict path runs. Reason: migration 20260926 established that no permission decision may depend on deployment environment alone, and a demo claim is a claim about DATA, not about a hostname.
- 2026-09-20 — A recommendation explanation is a REPLAY, not a second opinion: the item's own feature snapshot fetched by stored id, refused if its fingerprint moved, scored by REC-005's own `scoreSnapshot` under the ranking config the SLATE recorded. A slate whose config this build no longer carries is refused rather than explained with today's weights.
