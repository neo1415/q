# Q action parity audit — 2026-10-02

The founder's direction: every action a person can take with a mouse or keyboard can also be done by telling Q, from any page. This audit does three things:

- lists every user-initiated mutation route (api and q-api POST/PUT/PATCH/DELETE) and every web page;
- marks each one as a Q tool, a client action or offer, or exempt with a stated reason;
- records what was built to close the gaps.

The guard is `apps/q-api/test/route-capability-parity.test.ts`:

- a new route or page that is not classified fails;
- an exemption without a reason fails;
- (new) a mutation route mapped only to a read tool fails.

## Built in this pass

New typed Q tools. Each has an authorize step and goes through the same service the button uses, as the person.

Existing tools that can now be addressed by name, from any page (the founder's "Q won't do it" root cause):

- `save_company`, `unsave_company`, `pass_company`, `unpass_company` and `propose_express_interest` take a `company` name. It is resolved by `findRecordByName`, the same matcher `open_page` uses, among companies the person can already see; ids are still accepted. They no longer need the company on screen, and they are offered for every purpose.
- The relationship tools take `counterpartName`. This covers `propose_chat_message`, `propose_meeting`, `find_meeting_times`, `propose_reminder`, `propose_errand`, `propose_email` and `list_messages`. The name is resolved by `closestByName` among the person's own relationships, so a misheard name works ("nixo", "Nixon").

Routing of the four priorities:

| Request                               | Now                                                                                                                                                                                                                                            |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Send a message (connected)            | TOOL_REQUEST (reader v28) → `propose_chat_message` with `counterpartName` → a direct message card. Never an errand.                                                                                                                            |
| Pass, undo pass, save                 | `pass_company`, `unpass_company`, `save_company` by name, instant.                                                                                                                                                                             |
| Open chats, or a chat with X          | `navigate.RELATIONSHIPS`; `open_page` RELATIONSHIP_*_MESSAGES by name. Both existed already.                                                                                                                                                   |
| Book a meeting with a connected party | Hand-over MEETING → `find_meeting_times`, then `propose_meeting` at the first free time inside the reader's `timeWindow` → a direct call card. It falls back to the errand only when not connected, there is no calendar, or there is no time. |

## Still exempt, with the reason (person's actions)

These stay the person's own, by product rule or because only the browser can do them. The reason is the one in the parity test. Candidates to revisit are marked **revisit**.

- **Commitments** (record, confirm, adopt, dispute, withdraw): money facts need a human on each side (spec 6.6.14).
- **Billing checkout and portal:** the provider's hosted pages; Q never pays.
- **Push subscribe and unsubscribe:** the browser's own permission prompt and device setting. The channel switch itself is `set_notification_settings`.
- **Meeting assistant, add or remove:** a paid bot joins the call. **revisit** as an approval tool if the founder wants it.
- **Memory forget:** the person correcting Q's memory. **revisit:** "forget that" could be a Prepare → Approve on a named memory.
- **Conversation archive and message hide:** Q never ends or edits its own conversation (receipts rule).
- **Read markers** (chat and notices) and **feed observations:** not something a person asks for.
- **Onboarding session, Back, and briefing:** the loop's own tools act within the session.
- **Rehearsal start, turns, finish and screen:** the rehearsal is Q. Q opens it with `open_page`.
- **KYB:** a document the person uploads themselves. Q offers the page.
- **Email draft edit on a card:** asked to Q, Q prepares a new draft.
- **Readiness Blueprint:** a 501 stub; its tool comes with the feature.
- **Admin reinstate:** an operator's decision.
- **GateQ gateway administration (5 routes):** opened from the Gateway page. **revisit** with a Q gateway-rules tool.
- **`/discover/passed` (page):** its one action, Undo pass, is `unpass_company` by name from anywhere. Opening the list itself needs a `PASSED` navigate destination in the turn reader, whose versions HARDEN owns. **revisit** with the next reader version.

Offers (21 routes) where Q takes them to the control rather than doing it:

- uploads: documents, pitch video, profile photo;
- Google connect;
- the chat's block, unblock, report and unsend menu (a person's own safety decision);
- brand confirm;
- verification request.

Uploads need the person's file. The safety actions are deliberately the person's own.

## Follow-up: ADR 0040 (Proposed)

Per-gap patching is replaced by ADR 0040, which makes Q capability the app's own action and read registry.

- **Gap that closed it.** Q had no pitch facts and no way to change playback. "Let investors play my pitch video" was answered "no record".
- **Pitch.** `set_pitch_sharing` is generated from `pitch.details.set`. Audience and playback are one choice, and changing them needs approval.
- **Reads.** `read_my` covers media, documents and rehearsals, plus the WHAT EXISTS index on every turn.
- **Discovery decisions.** Save, unsave, pass and undo pass are generated from the registry. Their hand routes and hand tools are deleted.
- **Guard.** Hand-written mutation routes may only shrink.
- **Remaining areas.** The checklist, sized by area, is in `docs/adr/0040-q-capability-is-the-apps-own-action-and-read-registry.md`.
